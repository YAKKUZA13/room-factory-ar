## 2. Подготовка

1. Опубликовать `dist` под HTTPS (GitHub Pages или ngrok).
2. Открыть `marker/room-factory-marker-print.html`, напечатать **100%**; проверить линейкой 120 × 160 мм. Не использовать «fit to page».
3. Матовая бумага, ровный свет, без ламинации/бликов. Маркер положить на стол, рядом место под завод.
4. На устройстве открыть URL, разрешить камеру.
5. Включить диагностику `?debug=1`, чтобы видеть SLAM, marker status, pose error, FPS.
6. Для воспроизводимости отметить физическую точку на столе (риска/линейка) и угол платформы.

## 4. Дополнительные проверки

- **SLAM LIMITED во время BINDING**: привязка должна быть отклонена (`SLAM not NORMAL`), уже сохранённый anchor не теряется.
- **Marker lost во время BOUND_TRACKING**: завод остаётся на месте, пока SLAM не потерян; badge «Карточка потеряна».
- **Temporary placement**: после «Временно разместить здесь» и autosave/перезагрузки anchor в localStorage остаётся старым `kind:'marker'`, `T_M_F` не меняется.
- **Rebind**: «Перепривязать карточкой» не удаляет постройки, пересчитывает только `T_M_F`.
- **Масштаб**: 0.5×–1.0× до первой постройки; после первой постройки настройка блокируется; платформа ~0.5–1 м.
- **Высота**: кнопки ±5 см поднимают/опускают ghost; при наведении на стену hitTest не должен приниматься как горизонтальная поверхность.
- **Пауза**: производство стоит, камера/UI работают; после resume прогресс продолжается.
- **Экспорт/импорт на iOS**: проверить share sheet/скачивание; импорт не должен исполнять код и должен требовать подтверждения.

## 5. Протокол измерения relocalization

Для каждого повторного запуска:

1. Закрепить на столе физическую риску и линейку.
2. При первом размещении зафиксировать положение выбранного угла виртуальной платформы относительно риски (фото/координаты).
3. Закрыть вкладку (не просто свернуть), открыть URL заново, показать маркер.
4. После восстановления измерить расстояние между тем же углом платформы и рисковой отметкой; записать см.
5. Повторить 5–10 раз; отдельно записать угол поворота, если заметен.
6. Записать: устройство, ОС, браузер, освещение, расстояние до маркера, угол обзора, число успешных распознаваний.

## 8. Как запустить mock-проверку локально

```bash
npm run build
npm run preview
# в другом терминале:
npx playwright test tests/e2e/mock-ar.spec.ts --reporter=list
```

Или вручную:

- `http://localhost:5173/?mockAR=1&debug=1`
- «Начать в AR» → «Разместить завод» → «Привязать карточкой» → reload с `&mockOrigin=1.2,0,0.8` → «Продолжить в AR».
- В mock нельзя делать выводы о SLAM, камере, распознавании печати или FPS.
